## Known gaps

Found by the reviews of Milestones 4 to 6 and left for later, one line each.

- **macOS has not been run at all.** The front doors are written for it and type-checked on
  Linux; nothing has been linked, started or tested on a Mac, and CI waits for the public
  repository.
- **A macOS front door killed with SIGKILL leaves the original running.** macOS has no
  `PR_SET_PDEATHSIG`; SIGTERM, SIGINT and SIGHUP are passed on.
- **A busy macOS server front door takes a signal only after a second with no client.** It is
  passed on from the accept loop's idle step; a terminal's ^C may reach a macOS CLI original
  twice.
- **A front door written on Linux and committed must be written again on macOS** (it stops at
  start and says so).
- **Kept-alive connections close without `Connection: close`.**
- **A lifted server answers HEAD with 404, and a unit's HEAD answer has no `Content-Length`.**
- **The server front door decodes header bytes that are not UTF-8 lossily.**
- **Option clusters such as `-vx` skip the recorded-options check** of a CLI front door.
- **A hand-built front door finds itself through `/proc/self/exe`**, which resolves a symlinked
  `mojo/` to its target (generated ones are told the repository by `MOJO_ANYTHING_REPO`).
- **`lift` refuses a symlinked `mojo/`**, and recording again after `app front-door` makes
  `main.mojo` look hand-edited, which blocks `lift`.
- **`import a, b` stages only `a`** when a whole-app unit's imports are put together.
- **Two unit names that differ only in `-` and `_` collide.**
- **Glue that calls `run_with_stdin` with bytes that are not UTF-8 is untested.**
- **`analyze` rates Python packages used through CPython interop, and `std.testing` for RSpec,
  JUnit and xUnit, as good fits**, though a lifted binary still needs CPython and the tests are
  not translated.
- **The replacement table's tests for Ruby, Go, Java, TS, C#, Kotlin and ffmpeg names were
  deleted with the Rust crates and not written again for the Mojo table.**
- **`gate`'s `ported` and `unsafe` checks read `port.mojo` only**, not the helper `.mojo` files
  it imports.
- **The generated `binding.gyp` does not match the layout node-gyp writes (`build/Release`)**;
  mojo-anything builds the addon itself.
- **`--batch` `rank` with an omitted optional fixed parameter takes `undefined` as the minimum
  and returns `[]`**; ties are untested.
- **Two `--batch` specs on one function write `_batch_<f>` twice**, and the build fails.
- **`refresh` on a `mojo-node` unit reports the manifest's exports**, not the functions found
  in `port.mojo`.
- **A plain `Error` whose message starts with `TypeError: ` comes back as a `TypeError`.**
- **`bridge --kind node` takes any language** without checking that it is TS/JS.
- **A lone surrogate in a Java or Kotlin `String` argument is a `Panic`** where the original
  accepts it: a Mojo `String` cannot hold one.
- **A Mojo abort ends the JVM in an in-process shadow**, taking the host application with it.
- **Java `LinkedList` and `TreeMap` results throw `ClassCastException`, and `OptionalInt`,
  `OptionalLong` and `OptionalDouble` have no conversion**; `diff` reports them as mismatches.
- **The Java argument-rejection test checks the driver**, not a port that throws
  `IllegalArgumentException` where the recording has `ok: null`.
- **A Java or Kotlin class whose only public constructor takes parameters fails `java api`**:
  the wrapper keeps a public no-arg constructor only.

Found by the Milestone 7 measurement runs (2026-11-22):

- **`size` does not check a C unit that calls outside functions.** A facade over glibc says
  nothing about the size of the `strtol` its port reimplements, so such a unit is not compared;
  the same holds for any C that calls a function from outside the repository, or through a
  function-pointer parameter ([glibc](measurements/2026-11-22-glibc-facade.md)).
- **No Mojo timing is published.** `bench`, compile times and server throughput wait for a run on
  a quiet machine; nothing measured on rust-anything's Rust ports stands in for them.
