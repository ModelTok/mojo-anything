# Milestone 2: C to Mojo — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** C units are ported to Mojo as drop-in shared libraries that export the original names with the original C signatures, proven on ffmpeg's `rational.c` (46,764 cases) and the glibc facade (1,859 cases), and the Rust C bridge is gone.

**Architecture:** The `c-abi` kind keeps its name and meaning (a drop-in library with the C ABI); only the generated project changes from a Rust crate to a Mojo unit. `bridge` writes `mojo/<unit>/` with `port.mojo` (the port over Mojo scalar types, `Span`s for byte inputs and buffers, structs for by-value C structs) and `exports.mojo` (one `@export` per function: reads the C arguments, calls the port, writes outputs). Recording, the ctypes driver in `harness_c.rs`, the header and the C shadow stay as they are: they load whichever shared library `build` produced.

**Tech Stack:** Rust 2024 (the tool), Mojo via pixi, a C compiler for the originals, CPython ctypes for the driver, WSL Ubuntu 24.04.

**Spec:** `docs/superpowers/specs/2026-11-21-mojo-anything-design.md` (Phase 1, C row of "Bridge per source language", "build, gate, package").

Assumes Milestone 1 (`docs/superpowers/plans/2026-11-21-m1-python-to-mojo.md`) has landed: `crate::mojo::{MOJO_VERSION, available, command, missing_message}`, `codegen_mojo::{port_mojo, parse_port_mojo, STUB_MARK}`, `gate::mojo_checks`, `RType::mojo`, `docs/mojo-notes.md` and the mojo-anything names.

## Global Constraints

- All work and tests run in the WSL clone `~/github/mojo-anything` (Ubuntu 24.04), never `/mnt/c`.
- Mojo comes from pixi at `crate::mojo::MOJO_VERSION`; generated units pin the same version.
- Verify every Mojo API (exports, C types, pointers, struct layout) against the pinned stdlib source and add the confirmed spellings to `docs/mojo-notes.md` before generating code with them.
- Exported symbols use the original C names and signatures exactly as `codegen_c::c_prototype` prints them; no wrapper symbols are added to the drop-in library.
- `port.mojo` holds no pointers: pointers are read and written only in `exports.mojo`, each with a `# SAFETY:` comment, as `lib.rs` is today the only `unsafe` place.
- A header folder holding a file named like a C standard header goes on `-iquote` (pitfall: ffmpeg's `time.h`); the originals must compile before anything is read into a failed `record`.
- Before each commit: `cargo fmt --all`, `cargo clippy --all-targets -- -D warnings`, `cargo test`; update `docs/STATUS.md` when what works changes.
- Tests that need Mojo skip with a printed reason when `crate::mojo::available()` is false.
- Generated helpers are emitted only when the unit uses them.
- Prose in UK English.

## Review Focus

1. **`NULL` for a `const char *`.** The Rust port saw `Option<&[u8]>`; the Mojo port must see "no string" distinct from `""`, and a `NULL` buffer with length 0 must not be read. Test: Task 3 `c_null_string_is_none`.
2. **By-value struct layout.** `AVRational` (`int num, den`) passed and returned by value must match the C compiler's layout and calling convention on x86-64 and arm64, including a struct with a `double` and an `int`. Test: Task 1 `probe_struct_by_value`, Task 3 `c_struct_round_trip`.
3. **Buffers the function writes, sized by another parameter.** Writing must stop at the given length and leave bytes past it untouched (the recording holds the whole buffer). Test: Task 3 `c_buffer_not_overrun`.
4. **`char **` pointing into an input** (`OutPtr`, e.g. `strtol`'s `endptr`). The pointer written back must point into the caller's string at the same offset, not into a Mojo copy. Test: Task 3 `c_out_ptr_points_into_input`.
5. **Integer widths and wrap-around.** `int64_t` overflow in `av_rescale_rnd`, `unsigned` wrap and `char` signedness (`toupper(-128)`) must behave as the C original does, not raise or saturate. Test: Task 3 `c_int_widths_wrap`, Task 5 the glibc cases.

**Interfaces:**
- Consumes: Task 1 spellings, Task 2 generators, `codegen_c::{header, c_prototype}` (unchanged).
- Produces:
  - `pub fn exports_mojo(m: &Manifest, api: &PortApi) -> String` — one `@export` per function with the exact C prototype; converts C arguments to the Task 2 port types (a `NULL` `const char *` becomes `None`; `Buffer` and `Len` become one span of that length; `OutPtr` becomes an offset and is written back as `base + offset`, or left untouched when the port leaves `-1`); calls `port.<name>`; writes `Out` values back. A port that raises aborts the process with the message on stderr, as a Rust panic did (the recording's crash cases are run in a forked child by the driver).
  - `pub fn build(unit_dir: &Path, m: &Manifest) -> Result<PathBuf>` — `lib<lib>.so` (Linux) or `lib<lib>.dylib` (macOS) in the unit's `.mojo-anything/build`.
