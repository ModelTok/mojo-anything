# Decisions

Choices made so far, with reasons. Each one can be revisited.

## Product

| # | Decision | Reason |
| --- | --- | --- |
| D1 | A toolkit your agent drives, not a translator that calls a model itself. | No model cost or vendor lock-in; works with any agent. The checks are the part an agent cannot do reliably. Same shape as REA. |
| D2 | TypeScript/JavaScript first. | No existing tool covers TS/JS to Rust. C/C++ and Python are crowded (DARPA TRACTOR, C2Rust, Depyler). |
| D3 | Core plus one plugin per source language: `src/ts/`, then `src/lang/{python,c,go,ruby,java}.rs` on tree-sitter. | The plan, ordering, scoring and report are the same for every language; parsers, bridges and risks are not. |
| D4 | Written in Rust, parsing with oxc. | Fast (x18n, 27k lines, in about 0.1 s), and the tool uses the language it moves people to. |
| D5 | Shadow mode for every language. | Cloudflare FL2 ran old and new side by side in one process and moved traffic gradually. Tests prove a port; production traffic confirms it. |
| D6 | Name `mojo-anything` (was `carcinize`). Java packages use `mojoanything`, identifiers `mojo_anything`/`MojoAnything`, environment variables `MOJO_ANYTHING_*`. | Says what it does. The Rust trademark policy allows "Rust" in crate and repository names that refer to the language, as long as nothing looks official; the README says so. |

## `analyze`

| # | Decision | Reason |
| --- | --- | --- |
| A1 | A unit is a folder, or a file directly in a package's source root. | Folders are how most codebases mark modules; root files are usually standalone. |
| A2 | Skip `node_modules`, `dist`, `build`, `out`, `target`, `coverage`, `fixtures`, `__fixtures__`, `__snapshots__`, `playground`, `examples`, tool configs and `.d.ts`. | Not product code; fixtures hold sample projects that would distort the plan. |
| A3 | `.tsx`, `.jsx`, `.vue`, `.svelte`, `.astro`, and code importing Vue/React/Svelte/Nuxt or `vscode`, is kept in JS. | The prompt asked to flag UI-heavy parts; editor extension hosts make native modules painful. Their scripts are still parsed for imports. |
| A4 | Bridge: a Mojo port behind the Node-API shim (`Mojo (Node-API)`) when the unit or anything it imports needs Node, or its package's `src/` does; `Mojo (wasm)` otherwise, which `bridge` still ports for Node unless `--kind wasm` asks for the wasm module (M13). | Portable code must keep running in browsers; Node-only code gets the native bridge. Build scripts next to `src/` do not make a package Node-only. Until M4 Task 9 the two were napi-rs and wasm-bindgen. |
| A5 | Waves come from strongly connected components of the unit graph. | Leaves first means a Rust unit never calls back into JS; cycles must move together. |
| A6 | Risks are heuristics: method names like `slice` also match arrays. | False positives cost a look; false negatives cost silent bugs. Each risk lists its first lines so a human or agent can check quickly. |
| A7 | Readiness = 100 - weighted risks (log of count) - size - fan-in - dependency penalties + test bonus. | Log keeps big files from drowning in counts; fan-in pushes widely-used units later, where a mistake costs more. |
| A8 | Priority = half readiness, half value (loops and string work per line, tests, size between 80 and 600 lines). | Readiness alone picks trivial declaration files. A first port should be safe and worth the bridge. |
| A9 | The library table (`src/replacements.toml`, every language; `src/crates.toml` until M6) is hand-curated: each library maps to a Mojo stdlib module, a pixi package or `python:<module>` through CPython interop; unknown packages are reported as `unknown`, never guessed. | The prompt: flag missing equivalents instead of hand-rolling silently. |
| A10 | JSON output carries `schema: mojo-anything/analyze@1`. | Agents read it; it is a wire contract and gets versioned. |

## The loop

| # | Decision | Reason |
| --- | --- | --- |
| L1 | `bridge` splits `lib.rs` (bindings) from `port.rs` (plain Rust, `#![forbid(unsafe_code)]`). | Binding macros expand to unsafe code; the port itself never needs it, and it stays testable without a JS runtime. |
| L2 | `bridge` refuses to write into a non-empty folder, and refuses `blocked`/`keep` units without `--force`. | A port in progress is the user's work; the plan's verdicts should not be bypassed by accident. |
| L3 | napi bindings catch panics and throw JS errors (Rust era; the Mojo dispatcher answers a panic as `{"panic": ...}` and `index.cjs` throws it, see M12). | A panic unwinding into Node aborts the process; in shadow mode that would take the app down. |
| L4 | TS types map to `String`, `f64`, `bool`, `Vec`, `Option`; anything structured crosses as JSON. | Faithful to JS (numbers are f64) and always compiles; the port can introduce real types behind the binding. |
| L5 | `record` generates deterministic inputs from parameter types, with edge-case corpora, and derives one string argument from another half the time. | Reproducible recordings; search-like functions rarely hit on unrelated random strings. |
| L6 | Recording and diffing run in Node through generated scripts, with a lossless codec (`undefined`, `NaN`, `-0`, BigInt, Map/Set, key order, lone surrogates). | The comparison sees exactly what a JS caller sees. Lone surrogates were found by the fixture tests: JS `slice` can split emoji. |
| L7 | Both sides throwing counts as agreement; messages are not compared. | Error text is rarely a contract and would make every port fail on wording. |
| L8 | wasm builds used `cargo` + `wasm-bindgen-cli` (version-checked), not wasm-pack (Rust era; removed with wasm-bindgen, see M12). | wasm-pack downloads tools at run time, which fails offline and in locked-down CI. |
| L9 | Shadow mode returns the original's result, runs Rust second, and never lets Rust errors reach callers. | Shipping shadow code must not change behavior; only the report sees Rust. |
| L10 | The MCP server is a small hand-written JSON-RPC loop on serde_json. | The stdio transport needs four methods; an SDK would add churn for no gain. |

## Learned from porting x18n's core

| # | Decision | Reason |
| --- | --- | --- |
| X1 | `bridge` keeps exports in TS when their types hold functions (followed through imports, re-exports and `extends`), when they are generic, iterators, RegExp, or use `instanceof`; `--keep` adds more by hand. | 26 of x18n core's 55 exports are of this kind; ported, they would have changed the public API or broken silently. |
| X2 | Structured values cross with markers for `undefined`, NaN/Infinity/-0 and lone surrogates; the loader pads omitted structured arguments with `undefined`. | Each one produced real mismatches: `splitKey`'s `namespace: undefined`, `toWireRange` with NaN, `diffText` splitting an emoji, `isOutdated(change)` with one argument. |
| X3 | Overload signatures (no body) are skipped; type predicates map to `bool`; aliases resolve through imports; untyped defaults take the default's type. | `definePlugin` was listed twice; `isMessageLeaf` returned JSON; `KeyString` became JSON instead of `String`. |
| X4 | `record` installs a resolve hook, takes `--resolve-from`, and retries with `--experimental-transform-types`. | x18n's sources import without extensions, need `valibot` and `nostics`, and use parameter properties. |
| X5 | `bench` is a separate step, not part of `gate`. | Speed is not correctness, but it decides whether a port should ship: every x18n core port was correct and slower. |
| X6 | Risk guidance names `shift_remove` and UTF-16 string ordering. | `serde_json::Map::remove` reorders keys under `preserve_order`; JS `<` on strings compares UTF-16 units. |

## More languages

| # | Decision | Reason |
| --- | --- | --- |
| M1 | Every language maps its types into the TS-like dialect (`string`, `number`, `int`, `T[]`, `Record<string, T>`, `T \| undefined`). | The planner, input generator and port stubs stay one implementation; a language plugin only discovers, scans, resolves and lists exports. |
| M2 | Python uses a Mojo Python extension module (`PythonModuleBuilder`, built with `mojo build --emit shared-lib`), C a plain C ABI, Go and Ruby one Mojo JSON dispatcher (`dispatcher.mojo`, exporting `mojo_anything_call` and `mojo_anything_free`, JSON through EmberJson), and Java and Kotlin the same dispatcher through the Foreign Function & Memory API (M14), each behind a generated wrapper with the original API. Go also gets typed cgo exports (`exports.mojo`) for functions whose parameters and results are all numbers, booleans and strings; a unit made only of those needs no JSON. | The extension module and the C ABI are each language's native extension path; PyO3 was dropped with the move to Mojo, and an old PyO3 manifest asks for a fresh `bridge`. One dispatcher keeps the port's side identical across languages, and the generated wrapper keeps callers unchanged. |
| M3 | `diff` goes through the same wrapper callers will use (cgo package, Fiddle file, Java wrapper classes, the Python package around the Mojo extension). | The test must see what callers see: wrapper bugs, type conversions and exception mapping included. |
| M4 | Record and diff run in the source language's own runtime, with generated drivers; nothing is written into the original repository (Go builds its driver as a separate module with `replace`). | The original must run exactly as it does for its callers, and mojo-anything must not edit code it is migrating. |
| M5 | C records each case in a forked child; a crash is recorded as `crash: <signal>` and accepts any port behavior. | Inputs outside a C function's contract are undefined behavior: real glibc segfaults on `isalpha(INT_MAX)`. |
| M6 | C units port to Mojo drop-in shared libraries that export the original names with the original signatures. `port.mojo` sees no pointers: a `const char *` arrives as `Optional[Span[UInt8, ImmutAnyOrigin]]` (`None` for `NULL`), byte inputs and buffers as `Span`s, an `int *` as `mut Optional[Int32]`, a `char **` into an input as an offset, structs of scalars by value. `exports.mojo` alone reads and writes pointers, each with a `# SAFETY:` comment, and `gate` fails a `port.mojo` that names a pointer type. Pointers to lists, variadics and ownership-carrying returns stay in C. An old Rust `c-abi` crate (a folder with `Cargo.toml`) asks for a fresh `bridge`. | Ownership of buffers and structs has to be designed, not guessed; with the pointers kept in one generated file, the port is plain Mojo that cannot write past a buffer. |
| M7 | Errors compare by exception type (Python, Ruby), Java exceptions by class and message (since M5), Go `error` values by message, Go panics by being panics. A port signals one with `Err("TypeName: message")` (Mojo: `raise Error("TypeName: message")`). | Messages are rarely a contract, except Go's error strings, which callers often compare, and the JDK's, which M5's plan makes part of the port (`For input string: "x"`); every Java and Kotlin port here already gave the original's messages when the check was added. |
| M8 | Unannotated parameters used as numbers become `number` (Python, Ruby); Python recording passes integral numbers as ints in every fourth case. | `colorsys` got 1,709 garbage cases out of 1,800 without inference, and its int results were never recorded without ints. |
| M9 | `serde_json` runs with `float_roundtrip` in mojo-anything and in every generated crate. | The default parser can be one ULP off; Java's `Double.toString` exposed it in 43 cases. |
| M11 | Go and Ruby lost their Rust bridges: magnus (Ruby's extension), Go's binary wire and the Rust dispatcher. Ruby reaches the Mojo dispatcher through Fiddle, from a generated `ruby/<lib>_native.rb`. Integers beyond 64 bits and lone surrogates are refused with a named error. A Rust-era Go or Ruby unit (a folder with `Cargo.toml`) asks for a fresh `bridge`, and `--batch` for either answers "not yet". | Only Rust is banned, and Fiddle ships with Ruby; magnus and the wire were Rust. EmberJson reads integers up to 64 bits, so a bignum would otherwise arrive as a wrong float. Batches return once a Mojo batch path exists. |
| M12 | TS/JS units reach Mojo through a Node-API C shim (`node_shim.c`, compiled with `cc` against Node's headers) over the same JSON dispatcher as Go and Ruby, loaded by a generated `index.cjs` that keeps the original API, error classes and markers. napi-rs and wasm-bindgen are gone, with the binary wire of S7, the napi/wasm batch classes and `bridge --allocator`; an old `napi` or `wasm` manifest asks for a fresh `bridge`. `bridge` defaults TS/JS units to `mojo-node` (`--kind wasm` gives M13's `mojo-wasm`), and `package` answers "not yet" for npm until the packaging plan (M7). A recorded error never agrees with a port's `not ported: ` stub or `panic in <name>:` answer. | Only Rust is ruled out, and napi-rs and wasm-bindgen are Rust: the port must be Mojo, and Node-API is Node's own C ABI, so a few dozen lines of C are all that sit between them. The binary wire is deferred: JSON through the dispatcher is the one path until `bench` shows where a faster crossing pays on Mojo. |
| M13 | `bridge --kind wasm` (`mojo-wasm`) compiles the same JSON dispatcher to a wasm64 (memory64) module that the generated `index.cjs` instantiates in place of the Node-API addon. The unit's own Mojo 1.2.0 writes the IR for a baseline x86-64 CPU (`--target-cpu x86-64`, no SSE intrinsics), the IR is retargeted to `wasm64-unknown-unknown` (and its new float-constant syntax rewritten), and mojo-wasm's clang 22 and wasm-ld (`MOJOWASM_HOME`, default `~/github/mojo-wasm`) compile and link it with `src/mojo/wasm_runtime.c`: a bump heap behind Mojo's allocator, `malloc` and the host, reset after every call, a stack-trace stub so `raises Error` works, and 128-bit multiply and shifts. Floats are written by EmberJson as on native; the module must export the dispatcher and import only `env.mw_write`. A trap answers as a panic and starts a fresh instance. Needs Node 24+ (or a browser with memory64). | mojo-wasm's own wasm32 route does not carry the dispatcher: its pinned nightly cannot compile EmberJson 0.5.0, 64-bit IR read with 32-bit pointers folds the call to an endless loop, and IR for a 32-bit target (riscv32, i686, x32) breaks Mojo's `Variant` (its size and its layout disagree, so a growing `List` of JSON values loses tags). On wasm64 every probe matched native, and `String(Float64)` does not hang. |
| M14 | Java and Kotlin units reach Mojo through the Foreign Function & Memory API (`java.lang.foreign`, Java 22+, no preview features): generated `<Lib>Native` and wrapper classes with the original static methods call `mojo_anything_call` and `mojo_anything_free` of the same JSON dispatcher as Go, Ruby and TS. `bridge`, `record` and `build` stop on an older JDK. The Rust JNI crates are gone, and with them the Android profile (`build`, `record` and `diff --profile android`, the NDK and device support: `--profile` takes only `host`) and the Java binary wire and batches (S5, S6, S11, S14); a Java or Kotlin manifest of kind `ffi` asks for a fresh `bridge`, and `--batch` on `mojo-jvm` answers "not yet". | Only Rust is ruled out, and JNI needed native code on the Rust side; FFM is the JDK's own C ABI and needs none. Mojo does not target Android, so a port could not run there. The binary wire was Rust; it is deferred until `bench` shows where a faster crossing pays on Mojo (the JDK facade: about 1 µs per call, 0.03x). |
| M10 | Shadow per language: a Go package, a Ruby file that `prepend`s, `<Class>Shadow` Java classes, a C file with `-D` renames linked to the Mojo unit's shadow library (only the `mojo_anything_` names), and a `shadow` crate feature where the bridge is still Rust. | Each is the least invasive drop-in that language allows. |

## Speed

| # | Decision | Reason |
| --- | --- | --- |
| S1 | Rust era for Java (removed in M5, see M14): No JSON text on the hot path: Python converts objects in Rust (`pyconv.rs`), Java and Go get typed JNI and cgo functions for numbers, booleans and strings; JSON remains the fallback for other types in Java and Go. | JSON cost 10-50x the work: the colorsys port took 11.7 µs per call, CPython 0.5 µs. |
| S2 | Ports of untyped Python can use `pynum::Num`, Python's int-or-float, instead of `serde_json::Value`. | A `Value` per number cost about 600 ns per call in colorsys; `Num` keeps ints as ints at native speed. |
| S3 | `bench` decodes arguments once and times only the calls, in the original's process; C benchmarks link the original (renamed with `-D`) and the port into one C program. | Decoding per call, or calling through ctypes, hid the difference being measured. |
| S5 | Rust era, removed in M5 (see M14): Java (Go until the Mojo move, see M11): types beyond numbers, booleans and strings (lists, arrays, maps, structs, boxed and optional values, several results) cross as a compact binary wire, with encoders and decoders generated per type on both sides; the JSON dispatcher is only the fallback for types the wire cannot express. | `encoding/json` and the Java JSON codec cost 5-8 µs per call; the wire costs 0.4-1 µs, and a Java `List<String>` function became faster than Java. |
| S6 | Rust era, removed in M5 (see M14): Java ports report errors through a per-thread `String[2]` slot passed with each call; the generated Java throws the exception (constructors cached as method handles). Native code throws only for null arguments. | An exception raised from JNI costs about 1.5 µs more than one thrown in Java: the JVM unwinds the calling compiled frame on a slow path. A throwing `parseRadix` went from 3.0 to 1.8 µs; calls that succeed cost the same. |
| S7 | Rust era, removed in M4 Task 9 (see M12): TS (napi-rs and wasm-bindgen): synchronous functions with structured arguments or results get generated JS encoders and decoders over two buffers registered once (napi) or wasm memory (wasm). Objects travel by field index in the caller's key order, strings as UTF-16, unmodeled types as tagged values. Arguments of another shape, and port results that do not fit the TS type, send that call through JSON. | napi's own object conversion is 2-3x slower than JSON (one napi call per property); a hand-written wire prototype was 6-7x faster. Across the nine x18n core units the bridge cost fell by a third on average and `buildTree` became 2x faster than TS; the other leaf functions stay slower than V8's JIT. |
| S8 | `profile` runs a real workload under the language's own profiler (`node --cpu-prof`, `cProfile`) and ranks the repository's functions by inclusive time, with callers and the argument that varies per call. | Which code to port is a property of how it is called, not of the code: x18n's `fuzzyScore` is a leaf (slower in Rust per call) but a quarter of a search, called 50,000 times by one loop. |
| S9 | Batch classes (`--batch fn:param`): the items cross once, then `run` maps the function over all of them and `rank` returns the indexes of results above a minimum, best first (stable, like JS `sort`). Items and results are scalars or strings; numbers come back as typed arrays. | Research and a prototype agreed: the gains come from keeping data on the Rust side and using all cores, not from faster crossings. Indexes, not strings, cross back: the caller already holds the items. |
| S10 | A `<Function>Index` struct in `port.rs` (`new(items)`, `run(fixed args)`) replaces the default per-item loop; every crate with batches depends on rayon, wasm included, where it runs on one thread. | Preparing items once (lowercasing, masks) was the second 4x on x18n search; one `port.rs` then builds for napi and wasm. |
| S11 | Rust era for Java and Kotlin, removed in M5 (see M14): Batches in every bridged language (Go and Ruby until the Mojo move, see M11): magnus classes in the original Ruby module (the original's defaults and keywords kept), a Go type over a Rust handle (`New…`, `Run`, `Rank`, `Close`, a finalizer), and a Java `AutoCloseable` class freed by `close` or a `Cleaner`. Go strings cross packed in one buffer. | The same pattern pays everywhere: Go and Java, where per-call ports lose, gain 3-4x. |
| S12 | Rust crates with batches (Java and Kotlin JNI crates, removed in M5) use mimalloc as Rust's global allocator. `bridge --allocator rusty_alloc` (napi and wasm crates) went with those bridges in M4 Task 9; a manifest's old `allocator` field is ignored. | Ports allocate per item, and the system allocator serialized the threads: 1.6x on 4 cores in pure Rust, slower than one thread inside a Go process; 3.2x with mimalloc. Only Rust code uses that heap: every buffer that crosses is copied or freed by Rust. rusty_alloc is an option, not the default: the allocator lands in every generated crate, and mimalloc has years of production use behind it. Measurements by its maintainer are in #96 and #112. |
| S13 | `profile` per runtime: node `--cpu-prof`, cProfile, `go test -cpuprofile` read through `go tool pprof -raw` (inlined frames kept), JFR execution samples (`jfr print --stack-depth 256`), and for Ruby a TracePoint call tracer loaded through `RUBYOPT`. Sampled stacks share one aggregator; the batch parameter is found from each language's loop forms. | Each is the profiler that ships with the runtime; Ruby has none built in that samples, and stackprof is a gem the repository may not have. |
| S14 | Rust era, removed with the Go (M11) and Java (M14) bridges: String results go back in bulk: Go allocates one buffer of the results' total size and Rust copies into it on all cores (Go reads it with `unsafe.String`, one slice per result); Java gets one `char[]` of UTF-16 encoded on all cores, plus the lengths, and slices it with `new String(chars, at, len)`. Typed JNI strings cross as UTF-16 (`GetStringRegion`, `NewString`), not modified UTF-8. | Joining and freeing results on one thread, a second copy in Go, and one JNI call per Java string cost as much as the work: Java's batch went from 25 to 14 ms, its per-call port from 90 to 63 ms. |
| S15 | An index in `port.rs` may define its own `rank(<fixed>, min)`; the generated `rank` of every language then calls it instead of ranking `run`'s results. | Ranking can be cheaper than scoring everything: x18n's index narrows to the last query's matches and reads one-letter queries from a table, 0.8 to 0.5 ms per query, 1.7x to 11.5x on wasm. |
| S16 | `setup` writes each agent's own config (`~/.claude.json`, `~/.codex/config.toml`, `~/.cursor/mcp.json`, `~/.gemini/settings.json`, `~/.config/opencode/opencode.json`) and skills folder, adding only the `mojo-anything` entries, keeping key order, writing through a temporary file, and refusing files that do not parse. The command is the running executable's absolute path. OpenCode reads `mcp.servers` and takes the whole argv in `command`, so its entry is an array and a server left `disabled` is turned back on. | One command to try it in any agent is what most people need first; a tool that rewrites someone's settings must never lose them. |
| S17 | Mojo ports of TS/JS units batch through the dispatcher: the JS batch class checks and encodes its items once, each `run` sends them in one `<function>:batch` call that calls the port per item on one thread, and `rank` sorts `run`'s numbers in JS. No item table lives on the Mojo side, and there is no custom `Index` yet. | One crossing per run instead of one per item is where most of the win was; a table of handles in the library and `parallelize` wait until they are measured. |
| S4 | `bench` ends with a verdict: ship, keep the slower functions, port a bigger unit, or (for C) optimize the port. Faster is 1.1x or more, slower under 0.9x. | Numbers alone left the decision to the reader; Go and Java leaf functions cannot win per call, and the tool should say so. |

## Whole apps

| # | Decision | Reason |
| --- | --- | --- |
| W1 | The CLI front door is a Mojo binary in `mojo/app` (a pixi project: `main.mojo`, `original.mojo`, `units.mojo`), built with `mojo build --Werror` into `mojo/app/.mojo-anything/build`, with the repository passed as `-D MOJO_ANYTHING_REPO=<repo>` (read with `get_defined_string`); at run time `$MOJO_ANYTHING_REPO` wins, and without either the binary finds the repository five folders above itself. | Its own build folder keeps two front doors from overwriting each other's binary; the define and the variable find the original through a symlinked `mojo/` (pitfalls). |
| W2 | The front door starts the original with `fork`, `execvp` and `waitpid` through `external_call`, not the stdlib's `subprocess.run` (which captures stdout and drops the exit status), `posix_spawn` (it needs `environ`, a C global `external_call` cannot read, and opaque file-action structs) or Python's `subprocess` (a CPython dependency in every front door). stdin and stdout stay the front door's own descriptors, so bytes pass untouched; `run_with_stdin` writes the bytes glue read into a pipe with SIGPIPE ignored; an original killed by a signal makes the front door raise the same signal on itself. | The spike (2026-11-22) passed all three checks on this route: `cat` with `ff 00 fe` on stdin, `exit 3`, and `kill -TERM $$` seen as signal 15 by the caller. |
| W3 | `main.mojo` hands a command to its unit only when every option on the command line is one the recording saw for that command, in any case, a failing one included; anything else runs the original. | The Rust front door got this from clap rejecting unknown flags; the original defines what an option it was never recorded with means. A usage error that was recorded is checked by replay like any case, and counting only successful cases kept such cases on the original for ever, so no CLI with recorded usage errors could be lifted (quopri, 2026-11-22). |
| W4 | `app wire` on a CLI takes Mojo units only. Each wired unit's `port.mojo`, and the modules beside it that the port imports, are copied on every build into a package `mojo/app/.mojo-anything/build/units/<unit>/` (`-I` that folder), with the port's imports of its own modules rewritten to go through the package (`from json import` becomes `from <unit>.json import`); glue imports `from <unit> import port`. Glue is one `def <command>(args: List[String]) raises -> Int` per command in `mojo/app/glue/<unit>.mojo`; the stub returns `original.run(args)`. | Putting a unit's own folder on `-I` makes every unit's `port` the same name; a package over the folder itself fails because Mojo 1.2 refuses a file reached as both `helper` and `textops.helper`, and the port's bare sibling imports do not resolve inside a package. The copy leaves the unit's own sources as its bridge builds them. |
| W5 | `app lift` on a CLI works on a copy of `mojo/app`, the cases and the wired units (`.pixi` and `.mojo-anything` are never copied or touched), building and formatting the copy with the app's own pixi environment. In the copy it removes `original.mojo`, writes the lifted `main.mojo` when the file is still the generated one (compared after `mojo format`), regenerates `units.mojo` without kill switches, drops `import original` from the glue and strips each unit's bridge; then it runs each unit's `gate::mojo_checks`, `mojo format` on the app's sources, a search for calls into `original.`, `mojo build --Werror`, and the replay with its fallback count, and copies back only when none fails. | A pixi environment cannot move with a copy, and one per staged copy would install Mojo on every lift; checking the unit on the stripped copy checks what ships. Mojo has no test runner for command lines, so CI keeps `app replay --build`. |
| W6 | A library front door is a Mojo package in `mojo/app`: its `__init__.mojo` (rewritten by `wire`) re-exports each wired unit's port as `from <package>.units.<module> import port as <module>`. Every build puts the package together under `mojo/app/.mojo-anything/build/src/<package>/` (the app's `__init__.mojo`, and each unit's `port.mojo` and the modules it imports as the sub-package `<package>.units.<module>`, their imports of each other rewritten as in W4) and runs `mojo precompile --Werror` into `.mojo-anything/build/<package>.mojoc`. `wire` takes Mojo units with a manifest and refuses Rust crates; the lift strips each unit's bridge on a copy and needs each unit's Mojo checks, `mojo format` on `__init__.mojo` and `mojo precompile` to pass. | `mojo package` is deprecated in Mojo 1.2 ("use 'precompile' instead"; the output must end in `.mojoc`). A sub-package per unit keeps two units' `port` and helpers apart, and the re-export gives importers the unit's name (`from <package> import <module>`), as the Rust front door's `pub use <crate>::port as <module>` did; both were checked by spikes and `tests/library.rs`. |
| W7 | The HTTP front door is a Mojo server on the C library's sockets through `external_call` (`TCP_NODELAY` on every socket, keep-alive, chunked bodies, one request at a time), not Python's `http.server` through interop. | The spike (2026-11-22, `docs/superpowers/specs/2026-11-21-mojo-server-route.md`) passed 42/42 recorded cases both ways; the socket route was faster (about 2700 against 1600 req/s through the proxy), can call Mojo glue, needs no CPython, and its original ends with it. |

## Packaging

| # | Decision | Reason |
| --- | --- | --- |

Depending on Modular's own wheel needs no permission. Cost: installing the wheel pulls an 82 MB `mojo-compiler` wheel. The run path is reset so a package never points into the machine that built it (it named the unit's `.pixi` folder). |
| P2 | A wheel is built by an in-tree PEP 517 backend (`mojo_anything_backend.py`, standard library only, `requires = []`), not setuptools or maturin, tagged `cp<XY>-cp<XY>-<platform>` for the Python that recorded the unit, with `requires-python` for that minor version only. | `pip wheel` then works offline, and the wheel holds exactly the folder `package` wrote. The extension uses CPython's API through Mojo's interop and was only checked on the recording's Python, so the tag claims no other version. |
| P3 | The wheel installs the original's module name (`python_module`), except a standard-library name (`quopri`), which installs the wrapper's name (`quopri_mojo`) with a note. | The standard library comes before site-packages on `sys.path`, so a wheel's `quopri` would never be imported. |
| P4 | The npm, gem, Go, C and jar packages do not load the Mojo runtime themselves: it is found on the library path (`LD_LIBRARY_PATH`, `DYLD_LIBRARY_PATH`), when running and when linking. Only the wheel looks for it (P1). | Those runtimes have no package of Modular's to depend on, and a loader per language that searches for the runtime would guess at folders; the library path is how a C or Go program finds any shared library. Cost: a user of those packages sets one variable. |
| P5 | An npm package of a `mojo-node` unit falls back to the original's npm name (the nearest `package.json` above the unit), declared as an optional peer dependency, where no platform package fits; without a name it throws naming the platforms. A wasm package checks `process.versions.node` before compiling the module. | A platform with no Mojo build (Windows, Intel macOS) keeps working through the original instead of crashing on a missing file; an optional peer is not installed behind the user's back. |

## Known limits

- Tests that import a package by name credit the package, not a unit.
- `analyze` still guesses "compute-heavy" from loops and string work; `profile` measures (not for C:
  use `perf`). Go workloads must be `go test` runs, since Go profiles only from inside the process.
  The Ruby tracer slows the program several times; shares stay comparable.
- The bridge copies strings and structured values on every call. For fine-grained functions this
  dominates: measure with `bench`, and batch the loop around them. Batches take one scalar or
  string parameter (Ruby: any value) and return scalars or strings; not for C.
- Shadow mode compares synchronous Rust results; functions that mutate their arguments are run on
  already-mutated input by the second implementation.
- C: only scalar and `const char *` APIs cross the bridge; output buffers (`char *out, size_t *len`)
  and state structs stay in C. Functions defined through macros are not seen.
- Go: methods, generics, variadics, pointers, interfaces and channels stay in Go; struct
  parameters cross as JSON with their exported fields.
- Ruby: module functions only (`def self.x`, `module_function`); classes and methods that take
  blocks stay in Ruby. Without YARD tags, parameters not used as numbers cross as untyped JSON.
- Java: `public static` methods of public classes only; overloads, generics, `char` and object
  types stay in Java. `record` compiles the module's sources with `javac` alone, so code that
  needs Maven dependencies on the classpath cannot be recorded yet.
- No way yet to mark a recorded case as undefined behavior that does not crash (`ispunct(1000)`);
  remove it from `cases.jsonl` by hand.
- Go and Java: leaf functions are faster in their own language, since one call into Rust costs
  more than their work; `bench` recommends porting bigger units there. Interfaces, pointers,
  channels, Java objects other than strings, lists, arrays and maps, and Java primitive arrays
  other than `int[]`, `long[]`, `double[]` and `boolean[]` still cross as JSON.
- Ruby: aliases made with `alias` copy the original method, so shadow mode does not see calls
  through them.
