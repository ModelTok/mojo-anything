## Loop

```sh
mojo-anything record .   # record what the original does
mojo-anything build .    # build Java's Foreign Function & Memory API over the JSON dispatcher
mojo-anything diff .     # run the recorded cases against the port
mojo-anything shadow .   # run both in the app, log mismatches
mojo-anything gate .     # format, lint, tests, unsafe, API, diff
```

## How it was checked

OpenJDK 25.0.5.1, Mojo 1.2.0, x86-64 Linux (WSL2, Ubuntu 24.04), 2026-11-22. The original is
`original/Jdk.java`, placed at `src/main/java/com/example/jdk/` of a project with a `pom.xml`.

- `cases.jsonl`: 4,782 cases (286 throw), recorded with `inputs.jsonl` (the Rust-era inputs plus
  28 `formatDouble` values: `1.0E10`, the switch at 1e-3 and 1e7, the two-digit rule as in
  `4.9E-324` and `1.0E23`, binade edges, and values whose exact expansion ends in a 5). The port
  matches 4,782/4,782, and 4,492/4,492 on `cases.rust-era.jsonl`, the JDK 21 recording the Rust
  port passed. Every case recorded on both JDKs gives the same result; the 290 new cases come from
  the recorder's newer string and radix traps and the 28 values above. Since 2026-11-22 `diff`
  compares a thrown exception's message as well as its class: run again that way, the counts are
  unchanged (all 286 throwing cases, and the 226 of the JDK 21 recording, give the JDK's message).
  The wider check below was run before that and compared classes only.
- A wider check, not kept here (446,916 cases): 200,000 random bit patterns, 150,000 values in
  common ranges, every power of two and the first 3,999 subnormals through `formatDouble`;
  every BMP character through `parseRadix` at radix 36; and every code point, 128 at a time,
  through `upper`, `urlEncode` and `base64`. All match. It found two problems, both fixed:
  Mojo's case tables predate Unicode 16 and map the Greek letters with ypogegrammeni to title
  case where Java spells them out with capital iota (90 code points, kept in `_upper_apart`),
  and EmberJson read an escaped surrogate pair on planes 2, 4, ... 16 as the plane below (the
  Java codec now writes whole pairs as the character).
- `gate` passes: 173 lines of Mojo for 41 of Java, the size limit exactly.
- `bench` (run twice, AMD Ryzen 9 3900X, 12 cores / 24 threads, load average 1.2-1.8): every
  function is slower through the bridge, 0.03x overall. The crossing alone is about 1 µs
  (`reverseBits`: 9-10 ns in Java, 1,030 ns through Mojo); `formatDouble`, which does exact
  big-number arithmetic, takes 12-13.5 µs against 80-91 ns; `parseRadix` comes closest, 0.21x
  (1.7 µs in Java, most cases throwing, against 7.8-8.0 µs).
